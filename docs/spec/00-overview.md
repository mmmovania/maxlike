# Overview and technical decisions

## Goal
Recreate the look and workflow of 3D Studio MAX R3.1 on modern Windows, pixel-close at
100% scaling, and read R3-era `.max` files natively (port of the JS `max_loader`).

## Decisions
| Area | Choice | Why |
|---|---|---|
| Language | C++17, MSVC, Unicode | Native Win32, no runtime |
| UI | Raw Win32 + classic common controls behind a thin wrapper (`Window` base class, `this` in `GWLP_USERDATA`) | Exact classic bevel look; no heavy framework |
| Theming | No comctl32 v6 manifest (classic common controls) | Keeps 1999-style 3D controls |
| Font | `MS Shell Dlg` / MS Sans Serif 8 pt; viewport labels MS Sans Serif Bold 10 pt | Matches R3 |
| Viewports | OpenGL 3.3 core via GLAD; one shared context created on a hidden helper window; four child windows with `CS_OWNDC` | Matches Max's per-viewport windows; a helper avoids a black first viewport |
| Viewport drawing | Two small shader programs (lines/points with one matrix; lit triangles); ortho views use the measured pixel formula | Pixel-exact grid, tripods and wireframes |
| Viewport text | GDI renders the text into an off-screen bitmap; its pixels are drawn as 1-px points | Exact pixels, testable, no GDI-over-GL flicker |
| Command panel | Tabs, buttons, frames and rollouts painted by the panel from pure layout code; real classic `COMBOBOX`es only for dropdowns (Create's category list, the modifier stack, the sub-object level) | Exact look, scrolls as one; Windows already draws the dropdowns exactly |
| Icons | Original pixel art, generated by `tools/make_icons.py` into `res/*.bmp` (magenta = transparent) | No Autodesk art; reproducible |
| Build | CMake | VS and command line |
| `.max` import | Own CFB reader + zlib | Format already understood |
| Coordinates | Z-up, Max convention internally; right-handed quaternions (files store the conjugate: `Quat::FromMaxFile`) | Same as loader; one conversion point |
| Geometry | Primitives built like Max's, matching R3.1's vertex/face counts (`04-primitives.md`) | Imported Edit Mesh data addresses vertices by index |
| Redraw | On demand only | Same as Max |
| DPI | Per-monitor aware; all metrics are 96-DPI values scaled by `GetDpiForWindow/96` | Exact at 100%, clean elsewhere |
| Undo | Command pattern from Phase 3; commands refer to nodes by stable id | Hard to retrofit; pointers die when an undo recreates a node |
| Interaction | Mouse gestures as pure state machines (`scene::Creator`); windows only convert the mouse to plane coordinates; live changes are recorded as one undo step when finished | Testable without windows; undo matches what the user did |
| Selection | Part of the document: undoable ("Select"), referring to nodes by id | Matches R3's Edit > Undo Select; a selection can never point at a deleted node |
| Transforms | Live preview from each object's start, one undo step per drag; picking and dragging use the drawing's own projection | No drift, exact cancel, clicks land on what is drawn |
| Controls | Behaviour separated from look (`SpinnerModel` vs. painting); rollout contents as data (`ui::params`): rows with their own geometry (defaulting to the first measured layout), buttons, labels, radios, group boxes, disabled states, several rollouts per modifier | The look waits for measurements, the behaviour doesn't; new layouts are data, not code |
| Modifiers | A node holds a Derived Object (base + modifiers, bottom up) only once it has a modifier; each modifier has a parameter block like a primitive's; adding, removing, switching off and editing are undo commands | One mechanism for spinners, undo and (Phase 8) import; undo can unwrap a plain object again |
| Sub-objects | Edit Mesh edits the mesh as it is at its own level (the stack evaluated up to it), with moves stored in the object's space by vertex index | Modifiers above do not disturb editing; matches R3's Edit Mesh data |
| Hand-drawn classics | Radio buttons, checkbox ticks: drawn from measured patterns where Wine and Windows differ | Exact everywhere, independent of the system's drawing |
| Testing | Logic kept pure and unit-tested (CTest); UI checked by pixel comparison with R3.1 screenshots | Measurable fidelity |

## Out of scope / rules
- No Autodesk icons, bitmaps or name. All art is original.
- Writing real `.max` files is out of scope; save uses our own chunked format.
